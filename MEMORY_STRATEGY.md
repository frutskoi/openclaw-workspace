# 🎯 Оптимизированная стратегия памяти

## Текущая проблема
- Daily logs: 60KB за 2 дня (слишком много!)
- Нет автоматической загрузки контекста
- Дублирование информации

## Новая система

### Структура
```
MEMORY.md              ← Только критическая информация (54 строки ✅)
memory/topics/*.md     ← Контекст тем (91 строк ✅)
memory/cache/*.json    ← Структурированные данные (API keys, IDs)
memory/archive/        ← Старые daily logs
```

### Правила загрузки

**При старте main session:**
1. ✅ Загружать MEMORY.md
2. ❌ НЕ загружать daily logs
3. ❌ НЕ загружать все topic memory

**При ответе на вопрос:**
1. memory_search (быстро, дешево)
2. Если нужно → memory_get конкретного файла
3. Только релевантные части

**При работе в Telegram теме:**
1. Проверить memory/topics/<topic>.md
2. Если нет → создать краткий
3. Вести только текущий контекст

### Что хранить где

**MEMORY.md (критическое):**
- Системные принципы (Google сервисы, правила работы)
- Постоянные настройки
- Важные решения
- MAKC: 100-150 строк

**Topic memory (контекст):**
- Статус текущей задачи
- Ключевые настройки проекта
- Важные ссылки и ID
- MAKC: 50-80 строк на тему

**Cache (JSON):**
- API ключи и токены
- ID проектов/таблиц
- Настройки конфигураций
- Частоиспользуемые данные

**Daily logs (только critical):**
- Ошибки и их решения
- Важные события
- Уроки

### Автоматизация

**Еженедельная оптимизация:**
```bash
python3 /home/clawd/.openclaw/workspace/scripts/optimize_memory.py
```

**Скрипт делает:**
1. ✅ Извлекает структурированные данные в cache
2. ✅ Очищает MEMORY.md от дублей
3. ✅ Архивирует старые daily logs (> 7 дней)
4. ✅ Оптимизирует topic memory
5. ✅ Генерирует отчет по экономии токенов

### Cron для автоматизации
```cron
0 3 * * 0 cd /home/clawd/.openclaw/workspace && python3 scripts/optimize_memory.py
```

- Меньше контекста при загрузке → экономия токенов
- Быстрый поиск через memory_search
- Никакого дублирования
- Автоматическая очистка
