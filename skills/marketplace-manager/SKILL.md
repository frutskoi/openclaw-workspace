# Marketplace Manager — Wildberries + Ozon (мультиклиентский)

Управление процессами на обоих маркетплейсах для нескольких клиентов: единая точка входа для отчётов, юнитки, ОПиУ, цен и рекламы. Сам не ходит в API напрямую — делегирует профильным скиллам.

## Когда
Любая задача про WB или Ozon: «сводка по продажам», «ОПиУ за месяц», «юнитка», «проверь цены/рекламу», «что с остатками», «сколько заработали» — по одному клиенту или по всем сразу.

## Клиенты (мультирежим)

1. Реестр клиентов: `memory/cache/marketplace/clients.json` — для каждого клиента: имя, WB-таблица+ячейка токена, Ozon Client-Id+таблица+ячейка ключа, Apps Script ID. Читай реестр перед работой; если его нет или новый клиент — спроси у Босса доступы и допиши.
2. Текущие клиенты:
   - **Основной (Шумофф)**: WB токен в Настройки!B2 таблицы `1KZIFWQ61LUS17LpJTvemSX4jnjZJqB5hjl8E9w9a8fE`; Ozon Client-Id 959359, ключ в Настройки!C3 таблицы `1VUf_ryMnXuTkD7PBBfRu36fYScwPQtXDu75Dx_iyJgk`, Apps Script `1_ULT1JZsw-rFh0qXsjCkvr00VA3Xcp1rt5TwGf6Amqm75NF3-4oRwdWw`.
3. Клиент не указан в запросе и их >1 — спросить, по кому считать, или выдать по всем с разделением по клиентам.
4. В любом отчёте по нескольким клиентам — колонка/блок «Клиент». Смешивать цифры разных клиентов в одну строку нельзя.

## Диспетчеризация

1. Определи, какие клиенты, площадки и процессы затронуты.
2. Для деталей API читай профильный скилл и следуй его правилам:
   - WB: статистика, карточки, цены, реклама, ОПиУ → `wildberries-api` (лимит у каждого продавца свой, троттлинг внутри клиента строгий)
   - Ozon продавец: комиссии, юнитка, финансы → `ozon-seller-api`
   - Ozon реклама: расходы, ДРР → `ozon-performance-api`
3. Независимые клиенты/площадки можно опрашивать параллельно, лимиты внутри каждого соблюдать строго.

## Стандартные процессы

### Ежедневная сводка (по запросу «как продажи»)
- WB: `/api/v1/supplier/sales?dateFrom=<7дн назад>&flag=1`, `/api/v1/supplier/orders` — выручка, заказы, возвраты за вчера и с начала месяца.
- Ozon: `/v3/finance/transaction/list` за вчера + `/v2/posting/fbo/list` — выручка, доставки, отмены.
- Формат: таблица Клиент × Площадка: выручка, заказы, средний чек, возвраты, реклама (если быстро доступно).

### ОПиУ за месяц
- WB: `reportDetailByPeriod` v5 по правилам скилла (задержка ~45 дней — показывать последний готовый месяц, предупреждать).
- Ozon: `/v3/finance/transaction/list` с разнесением операций по правилам `ozon-seller-api` (строка «НЕ РАСПРЕДЕЛЕНО» обязательна).
- Итог: таблица ОПиУ Клиент × Площадка + суммарная прибыль по каждому клиенту и общая.

### Юнитка
- Ozon — только по модели из `ozon-seller-api` (средний тариф логистики, выкуп из истории, налог 8%, реклама 10% если не задано). WB — из отчёта реализации по факту. Себестоимость — из «Справочника» клиента; **перед расчётом проверять Справочник на пустые/#N/A себестоимости и дубли Offer ID — флажить, не молчать**.

### Цены и реклама
- WB: `discounts-prices-api` list, изменения через `upload/task` (цены в копейках!). Реклама: `adv/v1/promotion/count`, расходы `adv/v1/upd` (может быть пустым).
- Ozon: `/v5/product/info/prices`, реклама через `ozon-performance-api` (ДРР = расходы/выручка).
- Изменение цен или ставок рекламы — только после явного подтверждения Босса с diff до/после.

## Правила

- Токены никогда не выводить в чат/логи; читать из Настройки таблицы соответствующего клиента.
- Google-токен живёт ~1ч: перед серией запросов к Sheets/Apps Script обновлять через refresh_token.
- WB 429 → backoff 3s×(n+1), максимум 5 попыток. 204 = пусто, не ошибка.
- Задержка данных WB ~45 дней — всегда называть реальный период цифр.
- Числа сверять перекрёстно (заказы vs финансы), при расхождении >5% — флажить.
- При записи в Google Sheets строки могут сместиться между чтением и записью: сначала перечитать диапазон, найти целевые строки по Offer ID/названию, писать в найденные ячейки, затем перечитать и сверить результат. Писать в колонку по фиксированному номеру строки без сверки нельзя.
- Результаты кэшировать в `memory/cache/marketplace/<client>/*.json` с датой; старше 12ч — обновлять.

## Автоматизация (по отдельному решению Босса)
Через automations: ежедневная сводка утром, еженедельный ОПиУ — по каждому клиенту отдельно или общая. Создавать только после явного «да» от Босса.
