# 🎯 Оптимальное контекстное окно для OpenClaw

## Модель: zai/glm-4.7

### Лимиты контекста:

| Тип | Токены | Использование |
|-----|--------|--------------|
| **Максимальный** | 128,000 | Теоретический максимум модели |
| **Безопасный** | 60,000 | Оставляем запас на ответ |
| **Оптимальный** | **40,000** | Для максимальной экономии токенов |

### Почему 40,000 токенов оптимально?

**Экономия токенов:**
- Меньше контекста = меньше токенов на каждый запрос
- Вместо загрузки всех daily logs — используем memory_search
- Структурированные данные в cache (JSON) вместо длинных текстов

**Производительность:**
- Быстрый поиск через векторный поиск
- Меньше времени на обработку контекста
- Меньше памяти

**Гибкость:**
- Достаточно для сложных задач
- Можно загрузить нужное через memory_get
- Topic memory изолирована по проектам

## Автоматическая ротация сессий

### Скрипт проверки:
`scripts/check_context.py`

**Что делает:**
1. Оценивает размер текущего контекста
2. Сравнивает с оптимальным окном (40K токенов)
3. При достижении лимита — создает саммари
4. Рекомендует выполнить /new

**Статусы:**
- ✅ **OK** (< 28K токенов) — продолжай работу
- 🟡 **WARNING** (28-36K токенов) — скоро нужна ротация
- 🟡 **CRITICAL** (36-40K токенов) — завершай задачу, потом /new
- 🔴 **ROTATE** (> 40K токенов) — **выполни /new сейчас**

### Ручная проверка:
```bash
python3 /home/clawd/.openclaw/workspace/scripts/check_context.py
```

### Автоматическая проверка (каждые 2 часа):
```bash
# Добавить в crontab:
0 */2 * * * /home/clawd/.openclaw/workspace/scripts/cron_context_check.sh
```

## Стратегия ротации

### Перед ротацией (автоматически):
1. ✅ Саммари текущей сессии → `memory/cache/session_summary_YYYYMMDD_HHMMSS.json`
2. ✅ Важное из daily logs → MEMORY.md (через optimize_memory.py)
3. ✅ Topic memory остается доступной
4. ✅ Cache с данными остается

### После ротации:
1. ✅ Вся критическая информация в MEMORY.md
2. ✅ Topic memory доступна для каждого проекта
3. ✅ Cache с API keys, IDs и т.д.
4. ✅ Саммари прошлой сессии для контекста

### Что теряется:
- Детали conversation history (но это не критично)
- Мелкие логи (но важное уже в MEMORY.md)
- Полные daily logs (но саммари сохранено)

## Экономия токенов

### Без оптимизации:
- Контекст: 40K+ токенов

- Перегрузка при каждом запросе
