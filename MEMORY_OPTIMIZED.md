# Оптимизированная система памяти КожЗам

## Принципы экономии токенов

**Основная идея:**
- Минимум контекста при старте сессии
- Динамическая подгрузка при необходимости
- Никакого дубляжа информации
- Автоматическая очистка устаревшего

## Структура

### 1. MEMORY.md (Краткая справка)
**Только самое важное:**
- Системные принципы (Google сервисы, правила работы)
- Постоянные настройки
- Критические решения
- **МАКС: 100-150 строк**

### 2. memory/topics/<topic>.md (Контекст темы)
**Переменные данные:**
- Статус текущей задачи
- Ключевые настройки проекта
- Важные ссылки и ID
- **МАКС: 50-80 строк на тему**

### 3. memory/cache/<key>.json (Быстрая память)
**Структурированные данные:**
- API ключи и токены (JSON)
- ID проектов/таблиц
- Настройки конфигураций
- Частоиспользуемые данные

### 4. memory/YYYY-MM-DD.md (Только при необходимости)
**Логи для critical events:**
- Ошибки и их решения
- Важные события
- Уроки

## Стратегия загрузки

### При старте сессии (main):
1. ✅ Загружать MEMORY.md (только если main session)
2. ❌ НЕ загружать daily logs
3. ❌ НЕ загружать все topic memory

### При ответе на вопрос:
1. Сначала memory_search (быстро, дешево)
2. Если нужно → memory_get конкретного файла
3. Только релевантные части

### При работе в Telegram теме:
1. Проверить memory/topics/<topic>.md
2. Если нет → создать краткий
3. Вести только текущий контекст

## Правила обновления

### В MEMORY.md:
- ✅ Системные изменения
- ✅ Важные решения
- ✅ Шаблоны/паттерны
- ❌ Проектные детали
- ❌ Временные данные

### В topic memory:
- ✅ Статус задачи
- ✅ Ключевые настройки
- ✅ Важные ссылки
- ❌ Подробные логи
- ❌ Дублирование из MEMORY.md

### В cache (JSON):
- ✅ API ключи
- ✅ ID проектов
- ✅ Настройки
- ❌ Логи
- ❌ Текстовые описания

## Очистка

### Еженедельно:
1. Проверить MEMORY.md — удалить outdated
2. Проверить topic memory — архивировать завершенные
3. Удалить daily logs старше 14 дней
4. Проверить cache — удалить неиспользуемые ключи

### При завершении проекта:
1. Архивировать topic memory
2. Перенести важное в MEMORY.md
3. Очистить cache от project-specific данных

## Метрики эффективности

**Текущий подход:**
- MEMORY.md: 54 строки ✅
- Daily logs: ~60KB за 2 дня ❌ (много)
- Topic memory: 59 строк ✅

**Цель:**
- MEMORY.md: < 100 строк
- Topic memory: < 50 строк каждая
- Daily logs: только critical events
- Cache: структурированные данные
