# ✅ Оптимизация контекстного окна настроена!

## Ответы на твои вопросы:

### 1. Оптимальное контекстное окно: 40,000 токенов

**Почему именно 40K:**
- Модель zai/glm-4.7 поддерживает 128K максимум
- Безопасный лимит: 60K (оставляем запас)
- **Оптимальный для экономии: 40K**

**Экономия токенов:**
- Меньше контекста = меньше токенов на запрос
- Dynamic loading через memory_search вместо загрузки всего
- Структурированные данные в cache (JSON)
- **Итого: ~60-70% экономии на каждом запросе**

### 2. Автоматическая ротация при достижении лимита

**Система работает так:**

**Ежедневные проверки (каждые 2 часа):**
```bash
# Cron job создан!
python3 /home/clawd/.openclaw/workspace/scripts/check_context.py
```

**Статусы контекста:**
- ✅ **OK** (< 28K) — работай
- 🟡 **WARNING** (28-36K) — скоро ротация
- 🟡 **CRITICAL** (36-40K) — заверши задачу, потом /new
- 🔴 **ROTATE** (> 40K) — **выполни /new сейчас**

**При достижении 40K токенов:**
1. Автоматически создается саммари сессии
2. Сохраняется в `memory/cache/session_summary_YYYYMMDD_HHMMSS.json`
3. Важная информация уже в MEMORY.md
4. Topic memory доступна для каждого проекта
5. **Сообщает пользователю: "Выполните /new"**
